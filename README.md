# Sure Finance — Sites port

A personal-finance port of [Sure](https://github.com/we-promise/sure) for ChatGPT Sites. Track accounts manually, import transactions from files, and reconcile your ledger. This source snapshot corresponds to Site version 93.

## Getting started

Use Node.js 22.13 or newer and npm. Run the following from the repository root.

```sh
npm ci
npm run build
npm run db:migrate:local
npm run dev
```

For ChatGPT Sites hosting, create a private Site from this repository and bind its D1 database as `DB` and R2 bucket as `BUCKET`. The hosting manifest is ready for a new Site to receive its own project ID. The build produces the downloadable source archive.

## Reviewed bulk transaction deletion

This follows Sure's bulk deletion scope: selecting one transfer leg destroys the association and its fees while keeping an unselected counterpart. Confirmed transfer kinds become standard and lose only the kind lock; pending matches retain their original kind/locks. Reconciliation evidence on the survivor remains recorded. Recorded bill payments/settlement, converted goal usage, savings-match evidence and bill price history remain with deleted ledger links cleared. ## Original files and recovery

Files accepts PDF, UTF-8 CSV and standard unencrypted XLSX originals up to 25 MB, plus JPEG, PNG, GIF and WebP images up to 10 MB. The library allows 500 files per sign-in. Transactions support up to 10 receipt links each, using PDFs/images up to 10 MB. Open a saved transaction to upload receipts or attach an eligible original from your library. A single original can link to several transactions; split lines share their parent transaction’s receipts. Image previews authenticate privately. Removing a receipt link keeps its original; deleting an original removes all its receipt links while retaining financial records. Uploads do not parse figures or create transactions. Rename files or attach/unlink them through Files; Reconcile also accepts uploads for its current statement. Downloads always authenticate and verify owner-scoped references. Deleting a statement keeps its originals in the library. Deleting an original removes its file record and bytes while preserving financial figures.

Settings offers a version-31 JSON backup containing records, receipt links and file metadata, and a streaming ZIP with `finance-data.json`, `manifest.json` and available originals. The ZIP supports up to 500 MB of originals; larger libraries can download files individually. Unavailable files remain listed in the manifest. Select the ZIP directly in Settings to preview and restore financial records, then recover its included originals. Existing same-owner originals reconnect by SHA-256. Financial restore is atomic; original uploads finish separately and may be resumed with **Restore originals only**, without repeating financial replacement. The browser reads bounded pieces of a ZIP up to 512 MB and verifies every included original before financial preview. Original uploads remain at most 25 MB each, or 10 MB for images. Financial JSON/NDJSON retains the 8 MB / 20,000-record limit; formats 1–31 are accepted. No PDF/XLSX transaction extraction is added. The original Sure v2 ZIP can also be selected directly; its attachment manifest contains no original bytes and remains outside the current financial adapter. Attach those originals manually after importing finance records.

Failed uploads retain cleanup information for retry/removal. Active uploads cannot be deleted for 15 minutes; interrupted deletion keeps its record for retry. A financial restore waits for pending/deleting operations. Recovery can exclude incoming file metadata if the combined library would exceed 500 records. No storage keys or attempt tokens appear in API state or backups.

## Pending savings

Open a goal’s Funding & history panel to record a pending-savings pledge. Choose an incoming deposit/transfer entry or, for checking/savings accounts, a positive manually recorded balance update. Pledges last seven days and can be extended seven days at a time or cancelled while open. The entry window starts five UTC calendar days before creation and runs through expiry; amounts match within 0.50 currency units or 1% of the pledge. These reminders never move money, add goal progress, or enlarge earmarks. Goal progress uses recorded account backing.

New/changed manual transactions, transaction CSV imports, receiving transfer legs, manual recurring payments that create an inflow, and explicit statement/manual balance adjustments check eligible pledges after the financial save. Balance matching uses the positive difference from the prior total. Separate edits to the same dated valuation retain separate event evidence; investment/crypto market-value changes cannot match balance-update pledges. Older pledges claim first, and each transaction or balance-update event has one claimant. Pledges use goal currency. Foreign native deposits convert at their entry dates; matching retains both amounts and the applied quote.

Check recorded deposits offers a read-only preview and guarded confirmation, globally scoped to a goal or to one pending deposit from its history row. It can recover a missed deposit check; it deliberately does not infer historical valuation deltas after their previous values have been overwritten. The automatic matcher is a separate guarded write after the financial save. If the snapshot changed or matching failed, the saved financial entry remains successful and the response gives a matching warning, avoiding accidental duplicate money entries on retry.

Expiry is shown from the clock immediately in the UI and persisted by matching/check requests; no scheduled background job is configured. Closing a goal or unlinking an account cancels open pledges. Match snapshots remain visible when their source changes or is deleted, with a warning. JSON/ZIP financial backups retain this history and remap source/event IDs under the restoring owner. Limits: 5,000 pledge-history records per workspace and 200,000 comparisons per check; check one deposit at a time for a large queue. Contribution-based investment progress is implemented below.

## Investment goal progress

Goals can use current market value or net contributions. Automatic selection chooses contributions for a new investment/crypto-linked goal; existing goals retain their saved basis, including the balance basis applied by the additive upgrade. Explicit market-value selection remains available. Closed goals keep their basis and frozen completion amount until reopened. The funding panel shows both selected progress and actual market backing; reservations continue to use market backing, so a market loss does not create spendable money.

The calculation follows Sure’s `Goal#net_contributed_for` and `Balance::BaseCalculator#market_value_change_on_date`. Daily holdings changes telescope, giving net contributions as current investment cash plus the inverse cash flow of nonzero-share trades. Gains/losses and fees embedded in buys/sells stay in the market-change component; cash dividends, interest, standalone fees, transactions and balance adjustments affect contributions. Progress floors negative net contributions at zero. This is not tax cost basis or a time-weighted return.

Account Balance history and a goal’s Funding & history panel open Contribution history. Record a known net-contribution amount at the end of a date to establish a starting checkpoint; later cash/trade flows are applied once and later market movements are excluded. Checkpoints can be edited/deleted without changing account money. They keep their account/currency, support exact signed values, and are limited to one per account/date. Security transfers without contribution values and unexplained holding-quantity changes produce an explicit incomplete-history warning until a checkpoint covers them. Goals exclude an incomplete account from their progress subtotal and refuse completion or usage from that account until it is resolved. Current market backing remains visible.

Version-11 JSON/ZIP financial backups retain goal basis and contribution checkpoints and remap account references. A Sure v2 export with complete account-currency `Balance.net_market_flows` history supplies cumulative dated checkpoints. Missing market-flow rows are reported rather than treated as zero; inferred opening cash still follows the adapter’s documented starting-balance convention. Review a checkpoint when the source export lacks earlier history. Financial JSON retains its existing 8 MB/20,000-record recovery limits; imported checkpoints also count toward that limit.

## Manual exchange rates and transfers

Exchange rates accepts dated quotes and previewed CSV imports using `date,from_currency,to_currency,rate,notes` (notes optional). Rates are positive plain decimals with up to 18 fractional digits. Lookup uses the freshest direct or exact inverse quote on the requested date or within the previous five calendar days; a direct quote wins an equal-date tie. Missing rates never become one-to-one conversions. No external rate provider or bank/broker connection is configured.

Overview defaults to native-currency totals. Select combined conversion to translate account balances as of today, income/spending at each transaction date, and history at each month end. Missing rates produce explicit known subtotals and history gaps. Converted values or totals outside the exact safe-integer money range are unavailable with a range message. Native account records remain unchanged. Quote dates, sources and carry ages are listed.

Transfers support different currencies and optional additional source/destination fees. The amount entered is the outgoing principal; the receiving principal is rounded to the destination currency's minor unit. Fees are separate standard expenses: the source debit is principal plus source fee, and the net received is receiving principal minus destination fee. The applied rational quote, amounts and fee links are retained independently of future rate edits/deletion. A transfer-specific quote does not add a library rate. Both principals and linked fees save/delete atomically; change financial figures by deleting/recreating the complete group. Request identities prevent duplicate retries and reject reuse with different input. Restores deliberately clear those replay identities.

Version-12 JSON/ZIP financial backups retain rates, transfer snapshots and fee links; restored IDs belong to the current owner. Sure's v2 exporter omits the global rate library and transfer-fee associations. Its confirmed cross-currency principals retain their actual posted amounts and dates with an exact implied quote; independent exported fee expenses stay independent. Review them before deleting an imported transfer. Goal backing, usage, reserve targets and pledge matching support dated conversion as described below. Budget reporting now supports dated spending, cash and unpaid-bill estimate conversion below. Manual cross-currency recurring payments are implemented below. Cross-currency securities and automatic rate ingestion remain pending.

## Goals across currencies

A goal can use linked accounts in different currencies. Earmarks, proportional shortfall sharing and remainder claims stay in native account units; the goal's resulting share converts at today's dated direct/inverse quote. Goal progress and market backing convert independently. Budgets still reserve the actual native account shares, regardless of the goal's currency. Missing quotes, incomplete contribution history and out-of-range calculations show explicit known subtotals or unavailable figures. Completion refuses an incomplete conversion; a completed goal keeps its frozen goal-currency amount after later rate changes.

Record usage in goal currency. The form previews the native amount released using the usage date's quote. Native releases round upward to the source currency's minor unit; the remaining target cap rounds downward. A small remainder below one native unit can remain in progress. Usage saves the goal amount, native release, date, exact ratio and quote provenance together. Linking a ledger expense checks its native outgoing value; shrinking it below that recorded native amount is blocked. Deleting a linked expense keeps the usage and conversion history. These actions do not create payments or account outflows.

Pending-savings promises also use goal currency. Foreign incoming entries and positive manual balance deltas convert on their entry dates before tolerance matching. The saved match retains native amounts/balance totals and its goal-currency conversion. A later quote edit cannot change historical matches. Missing, zero-rounded or out-of-range conversions keep the pledge open and appear in the matching preview or the successful financial-save response. Add a historical quote and check recorded deposits to recover an incoming transaction match. Historical balance deltas are not inferred; record a positive balance update with its quote available.

A months-of-expenses reserve converts expense entries at their dates to workspace currency, computes the median of expense-active months, multiplies by the month count, then converts that target at today's quote. Any missing expense/target quote prevents derivation of a partial target: saving preserves the supplied existing/fallback target; Refresh refuses the change. No automatic refresh schedule is configured.

Version-13 JSON/ZIP financial backups retain usage and match conversion snapshots. Versions 1–12 remain accepted, with null conversions for old same-currency history. Recovery validates amounts, currencies, quote dates and rounding, remaps owner-local links, and never imports authorization. The additive D1 migration preserves previous financial values and upgrades transaction guards to compare native usage amounts. Goal usage and pledge histories keep account currencies locked after unlinking.

## Budgets across currencies

Budget plans can report accounts in different currencies. Spending and refunds convert at transaction dates using the freshest direct/inverse manual quote within the previous five days.
